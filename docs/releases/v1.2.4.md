# V1.2.4 · 客户端更新流程

网页与客户端分别检查、分别显示版本。网页通过 Service Worker 更新并刷新生效；原生悬浮窗和安装等系统能力必须安装客户端。

## 更新范围

- Windows x64：原生后台下载，显示进度和错误；检查 HTTPS 发布信息、架构、文件长度及 SHA-256，完成后启动交互式安装程序并退出旧进程。安装向导可能需要用户确认，完成后按向导打开应用。
- Android（code 9）：后台下载、进度、SHA-256、应用 ID、版本和原签名校验；完成后打开系统安装器，用户确认安装。首次安装需允许「安装未知应用」，返回后可继续安装。不承诺静默安装或自动重启。
- 此前版本没有更新协议，需要手动覆盖安装一次。提供复制下载页地址的入口，避免旧 WebView 无法处理下载链接。
- Windows ARM64、Linux、macOS 此轮继续手动更新，保留已有下载及架构元数据。

## 行为与限制

- 下载地址和校验值由原生端从固定 HTTPS 来源读取，页面不能指定任意安装包。
- 失败不启动安装，提供原因和重试；应用进程重启后可重新下载，不提供断点续传。
- Android 页面重载会重新连接当前下载状态；安装权限和确认由系统管理。
- 下载完成后自动打开安装程序，仅在用户点「下载并安装」后启用，轮询不会反复弹出安装器。
- 不使用 Tauri updater 的签名差量协议。本版是下载完整安装包的应用内更新，不能把原生功能当作网页热更新。

## 验证

- Web 单元测试与 TypeScript；真实浏览器覆盖 Windows/安卓新旧客户端、浏览器、失败重试、下载进度及安装器不重复弹出。
- Windows Rust 版本、架构及包大小校验测试；使用相同 reqwest 原生依赖验证公网 TLS、分块下载和 SHA-256。未在用户电脑执行安装器。
- 独立安卓模拟器使用临时签名及隔离包验证真实文件写入、进度、重复下载保护、SHA-256、签名不符拦截、安装权限提示和安装器交接；未实际覆盖安装用户应用。
- 正式安卓包使用原证书签名，三 ABI，64 位库 16KB 对齐；服务端使用隔离数据库预检，再进行带源文件校验的切换。
